## SKILL.md

name: product-definition
description: Turns idea and research into a defined product, scope, core features, and what is explicitly out. Use after research is complete, before planning. Not split into sub-skills, this phase stays one sequence of steps.

## Steps

1. Read docs/product/idea.md and every file under docs/product/research/.
2. Draft three candidate scopes: minimal, realistic, ambitious.
3. Ask the user to pick one, or push back and negotiate if none fit the research.
4. Write the chosen scope, core features, and an explicit "not building this yet" list to docs/product/definition.md.`} />

## Why this stays one skill

[Research](/docs/claude/showcase-research) split into three sub-skills because each one is independently useful, you might rerun just the competitor scan without redoing trends or market sizing, and each produces its own distinct artifact. None of that is true here. Step 2 cannot run before step 1 finishes, step 4 needs the user's answer from step 3, and nobody would ever invoke "draft three candidate scopes" on its own. When steps depend on each other in a strict line and none is independently reusable, numbered steps inside one `SKILL.md` are the whole answer. Splitting them into four sub-skills would only add files to route through, not flexibility.

## Where it fits

Invoked by [the orchestrator](/docs/claude/showcase-orchestrator) as phase 3, after [Research](/docs/claude/showcase-research). Hands off to [Planning](/docs/claude/showcase-planning), which reads `docs/product/definition.md` as its own starting point.
