<InOneMinute>

- Two files, both in `~/.claude/`, both personal to you, both apply to every project.
- `CLAUDE.md` is instructions you write. `settings.json` is configuration Claude Code enforces.
- Do this once. It stops you re-typing the same preferences every session.
- The thing people get wrong: putting a hard rule in `CLAUDE.md` and assuming it always holds. Claude treats `CLAUDE.md` as advice, not enforcement — a rule that must never be broken belongs in `settings.json` or a hook instead.

</InOneMinute>

## What you are about to create

Two personal files apply to every project you open in Claude Code, because they live in your home directory rather than a repo. You write them once.

## 1. A personal CLAUDE.md

Create `~/.claude/CLAUDE.md` with the preferences you would otherwise repeat in every session — your preferred commit style, a note about which package manager you use, how verbose you want explanations to be.

<CodeBlock language="markdown" filename="~/.claude/CLAUDE.md" code={`# Personal preferences

- Prefer pnpm over npm unless a project already uses something else.
- Keep commit messages under 72 characters on the summary line.
- When unsure between two approaches, ask instead of guessing.`} />

- This file loads at the start of every session, in every project.
- Keep it short. Files over 200 lines dilute how closely Claude follows them.

<CheckItWorked>
Start Claude Code in any project and type <code>/memory</code>. Your file is listed under the personal scope.
</CheckItWorked>

## 2. A personal settings.json

Create `~/.claude/settings.json` with a model default and a hard deny on reading secrets.

<CodeBlock language="json" filename="~/.claude/settings.json" code={`{
  "$schema": "https://json.schemastore.org/claude-code-settings.json",
  "model": "claude-sonnet-5",
  "permissions": {
    "deny": ["Read(./.env)", "Read(./.env.*)"]
  },
  "cleanupPeriodDays": 90
}`} />

- `permissions.deny` wins over any `allow` rule in any other settings file, including a project's. This is the one setting worth having everywhere.
- `cleanupPeriodDays` controls how long session transcripts are kept before Claude Code deletes them.
- The `$schema` line is optional. It gives your editor autocomplete and catches typos.

<CheckItWorked>
Run <code>/permissions</code> inside Claude Code. Your deny rule is listed even in a fresh project with no settings of its own.
</CheckItWorked>

## 3. Turn on Memory in the apps

In claude.ai or Claude Desktop, go to Settings → Memory and turn it on. Claude will start noticing durable facts about how you work and recalling them in later conversations — separately from anything in Claude Code, since the two do not share memory.

## 4. Switch your default Style

In the same settings area, switch your default Style from Normal to Concise. Most people find Claude's default writing style longer than they want for everyday work; Concise is the fastest fix, and you can always ask for more detail on a specific reply.

## What you get for this

You stop re-typing the same instructions every session, in both Claude Code and the apps. That is the whole benchmark for this page — once that is true, move on to [Which one should I use?](/docs/claude/choose) to figure out what belongs in a *project's* configuration instead of yours.
