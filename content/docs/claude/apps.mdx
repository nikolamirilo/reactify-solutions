<InOneMinute>

- Skills in the apps use the same `SKILL.md` format as Claude Code, uploaded as a ZIP instead of committed to a repo.
- A Project is a bounded workspace: instructions, a file library, and shared conversation context, all in one place.
- A Style controls tone and format. It is not a procedure. That is still a skill.
- Do not expect a skill uploaded here to also appear in Claude Code. It does not, until you upload it there separately.

</InOneMinute>

## Skills in the apps

Skills work the same way here as in Claude Code, a folder with a `SKILL.md` file, loaded on demand rather than all at once, but you manage them differently. Upload a skill as a ZIP under Customize, then Skills (or Settings, then Capabilities, depending on your plan), then toggle it on or off. Claude applies a relevant skill automatically, or you can invoke one directly with `/skill-name`.

Pre-built skills ship for PowerPoint, Excel, Word, and PDF. Several partner companies publish their own too, Notion, Figma, and Stripe among them.

<Callout type="warn" title="Skills do not sync across surfaces">

A skill uploaded here is not available in Claude Code, and a skill in your repo's `.claude/skills/` is not available here, until you upload it to each surface separately. Keep the source file in your own git repo as the one canonical copy, and treat each surface's upload as a deploy step.

</Callout>

## Projects

A Project bundles three things that stay together across every conversation inside it: instructions (a system prompt for that Project specifically), a file library, and shared context between conversations. Projects have their own memory, walled off from your global one. Nothing you discuss in a Project's conversations shows up in an unrelated chat's memory, or the other way around.

Use a Project when you have a bounded piece of work with specific files and context. Reach for a skill instead when what you actually have is a reusable *procedure* that should work the same way across different Projects and conversations. A Project cannot travel with you the way a skill can.

## Styles

A Style changes how Claude writes, its tone and output format, for the rest of a conversation or per message. Four presets ship by default: Normal, Concise, Explanatory, and Formal. You can also build a custom one from writing samples or plain instructions.

Styles, your profile preferences, Memory, and a Project's instructions all load together and combine, rather than one overriding the others. Put stable facts about yourself and how you like to work in your profile preferences. Put swappable tone in a Style. Put a reusable task in a skill.

## Memory

Memory saves facts across separate conversations, and is off by default. Turn it on at Settings, then Memory. Claude signals when it draws on something it remembers, and you can view, edit, pause, or delete any entry, or reset all of it (which also clears every Project's memory, with no way to undo it).

Global memory, synthesized from your standalone chats, and a Project's memory are kept separate and do not read each other.

## Connectors

Connectors are the app-facing equivalent of MCP. A web connector runs on the provider's cloud, and a desktop connector runs locally on your machine. Both are set up inside the desktop app, through Cowork. Desktop Extensions package a local MCP server into a single installable file for one-click setup, and store any secrets in your operating system's keychain rather than in a config file.

## Cowork

Cowork is a desktop app that runs Claude as a persistent agent alongside you, with access to your local files and your configured connectors. It is distinct from the stateless chat window and from the terminal-first Claude Code, and it syncs skills from your account at the start of each session. Availability depends on your plan and, inside an organization, on whether an admin has turned it on. Where it is not available, Projects are the fallback for the same kind of bounded, ongoing work.
