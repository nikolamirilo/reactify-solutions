<InOneMinute>

- Claude Code keeps every customization in a plain file, in your repository or your home directory: settings, memory, hooks, skills, subagents, commands, plugins, MCP servers.
- That means each one is versionable, diffable, and reviewable in a pull request, the same as any other code.
- Skills are worth knowing on their own. `SKILL.md` follows an open standard, so the same skill folder can work outside Claude Code too, wherever something reads that same format.
- Nine or ten file types is a lot to keep straight at once. [Which one should I use?](/docs/claude/choose) turns the choice into a table instead of a wall of text.

</InOneMinute>

## One habit worth building

Everything that shapes how Claude Code behaves, a settings file, a project memory file, an automation script, a reusable procedure, is a plain file that lives in your repository or your home directory. That means it is versionable, diffable, and reviewable in a pull request, exactly like the code sitting next to it.

Hold onto that one idea before the rest of this reference gets specific. A dozen different file types can sound like a lot to learn. They are all the same kind of thing underneath: text, in git, doing one clearly scoped job.

## What is on this reference

| File or folder | What it does |
|---|---|
| `settings.json` | Permissions, model choice, hooks, MCP servers |
| `CLAUDE.md` | Durable facts and conventions Claude reads at the start of every session |
| Auto memory & `.claude/rules/` | The rest of Claude's memory system, see [Memory management](/docs/claude/memory) |
| A skill (`SKILL.md`) | A reusable procedure, loaded only when the task matches |
| A subagent | One task, run in its own isolated context |
| A slash command | A prompt you trigger yourself, by typing `/name` |
| A hook | A command that runs automatically, with no way for the model to skip it |
| MCP (`.mcp.json`) | A live connection to an external tool or data source |
| A plugin | Several of the above, bundled for a one-step team install |
