<InOneMinute>

- Claude has two separate customization worlds: **Claude Code** (files in your repo) and **the Claude apps** (settings in your account).
- Claude Code's files are versionable and shareable through git. The apps' settings live in your account and follow you between devices.
- **Skills** are the one artifact that works in both. It is a folder with a `SKILL.md` file, portable because it follows an open standard.
- Do not assume a skill you upload to claude.ai also shows up in Claude Code. It does not. Nothing syncs automatically between the two worlds.

</InOneMinute>

## Two worlds, one habit worth building

Claude Code is the terminal, IDE, and web tool developers use to write software. Every way you customize it, a settings file, a project memory file, an automation script, is a plain file that lives in your repository. That means it is versionable, diffable, and reviewable in a pull request, the same as any other code.

The Claude apps - claude.ai, Claude Desktop, and Claude Cowork - work differently. Customization there lives in your account: uploaded skills, saved Projects, a writing Style, things Claude remembers about you. None of it is a file you can commit. It follows you when you sign in somewhere else, but it stays invisible to your team unless you turn on sharing.

Skills are the bridge. A `SKILL.md` file works in Claude Code, the Claude API, and the apps, because Anthropic published the format as an open standard. Everything else on this list, settings, hooks, subagents, Projects, Styles, belongs to one world only.

## The two worlds, side by side

| | Claude Code | Claude apps |
|---|---|---|
| Where it lives | Files in your repo | Your account |
| Shared with your team | Yes, via git | Only if you turn on sharing |
| Survives a fresh machine | Yes, clone the repo | Yes, sign in |
| Skills | `.claude/skills/*/SKILL.md` | Upload a ZIP in Settings |
| Persona / tone | Output Styles, subagent prompts | Styles |
| Reusable memory | `CLAUDE.md` | Projects, Memory |
