<InOneMinute>

- This page is a lookup table, not a tutorial. Bookmark it and come back when you need a path.
- Every Claude Code artifact has two common locations: your home directory (`~/.claude/`, personal, every project) and your repo (`.claude/`, shared with your team via git).
- The thing people get wrong: assuming the strongest-sounding file always wins. For permissions specifically, a `deny` rule wins regardless of which file it is in.

</InOneMinute>

## Claude Code: where each artifact lives

| Artifact | Personal (all projects) | Project (shared via git) |
|---|---|---|
| Settings | `~/.claude/settings.json` | `.claude/settings.json` |
| Local-only settings | — | `.claude/settings.local.json` (auto-gitignored) |
| Memory | `~/.claude/CLAUDE.md` | `./CLAUDE.md` |
| Hooks | inside either `settings.json` | inside either `settings.json` |
| Skills | `~/.claude/skills/<name>/SKILL.md` | `.claude/skills/<name>/SKILL.md` |
| Subagents | `~/.claude/agents/<name>.md` | `.claude/agents/<name>.md` |
| Slash commands | `~/.claude/commands/<name>.md` | `.claude/commands/<name>.md` |
| MCP servers | `~/.claude.json` | `.mcp.json` (repo root) |
| Output styles | — | `.claude/output-styles/*.md` |

An enterprise-managed file can also exist above all of these — `managed-settings.json` and a managed `CLAUDE.md`, deployed by an organization's IT and impossible for anyone below that level to override.

## Which file wins

For most settings: **the more specific file wins.** Your personal local file beats your project's shared file, which beats your personal global file. A company-managed file beats everything and cannot be overridden by anyone.

Permission rules are the one exception, and it is worth memorizing: **`deny` always wins, regardless of which file it is in.** A `deny` in your weakest file beats an `allow` in your strongest one. This is deliberate — it means a safety rule can never be quietly switched off by a more specific file.

<CodeBlock language="json" filename="~/.claude/settings.json — the weakest file" code={`{ "permissions": { "deny": ["Read(./.env)"] } }`} />

<CodeBlock language="json" filename=".claude/settings.local.json — a stronger file" code={`{ "permissions": { "allow": ["Read(./.env)"] } }`} />

Claude Code still refuses to read `.env`. See [settings.json](/docs/claude/settings) for the full precedence order across all four files.

## Claude apps: where each artifact lives

Nothing here is a file path — everything is a setting inside your account.

| Artifact | Where |
|---|---|
| Skills | Settings → Skills (or Customize → Skills) |
| Memory | Settings → Memory |
| Styles | Settings → next to where you pick a model |
| Projects | The Projects tab, top level |
| Connectors | Set up inside the desktop app, through Cowork |
| Desktop Extensions (`.mcpb`) | Claude Desktop's extension directory |

Nothing in this table syncs with the Claude Code table above. A skill uploaded to claude.ai is not available in Claude Code, and a skill in your repo's `.claude/skills/` is not available on claude.ai, until you upload it there separately.
