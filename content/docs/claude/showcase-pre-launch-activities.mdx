<InOneMinute>

- Phase 3 of 3, the last phase in this example, invoked once [Implementation](/docs/claude/showcase-implementation) reports a working, deployed build.
- Invokes four sub-skills, but not all in a strict line: validation runs first, then the other three run independently of each other.
- Nothing invokes anything after this phase. Once all four sub-skills report back, the process is done.

</InOneMinute>

## Invoke

1. /validation-and-testing first. There is no point polishing a product that does not work.
2. /seo, /accessibility, and /ui-ux-polish, in any order, once validation passes. None of the three depends on either of the others.

Report back once all four are done. That is the whole process, end to end.`} />

- This is the one phase in the tree whose sub-skills are not all sequential. Validation gates the other three, but those three do not gate each other. The description says so directly, "in any order", rather than leaving Claude to invent a sequence that does not matter.
